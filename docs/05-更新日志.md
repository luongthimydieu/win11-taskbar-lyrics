## v1.2.9（2026-10-18）

优化歌词跟手（实测有约 0.5 秒延迟）：

1. **SMTC 轮询 2 秒 → 0.5 秒**：位置锚点更细，切行更及时；
2. **本地单调歌词时间轴**：网易云等播放器的 SMTC 时间轴经常一直给 0/空值，旧实现每轮轮询都把锚点重置；现在只在换歌、明显跳转、播放/暂停切换时重新锚定，其余时间用单调时钟平滑推进（实测 SMTC 位置恒为 0 时歌词仍能正常逐行滚动）；
3. **用 `LastUpdatedTime` 做位置锚点**：SMTC 时间轴自带“这个 position 采样于何时”，比“轮询收到消息的时刻”更准；对 1601 哨兵值/过长偏差会自动回退；
4. **新增歌词同步微调**：右键/托盘 →「🎶 歌词同步微调」→ 歌词更早/更晚 0.2s、0.5s、重置；配置项 `lyric_offset_ms`（正数=歌词更早）；
5. 说明：0.5 秒延迟可能来自播放器上报粒度、系统 SMTC 缓存或 LRC 时间轴本身，微调是最可靠的兜底；
6. 版本号 → 1.2.9；已发布 GitHub Release：
   <https://github.com/luongthimydieu/win11-taskbar-lyrics/releases/tag/v1.2.9>。

## v1.2.7（2026-10-17）

修复“全屏时组件隐藏了又会闪出来 / 一直闪”：

1. **根因**：组件 hide 之后，每 5 秒一次的“任务栏重新置顶”调用用了带 `SWP_SHOWWINDOW` 的 `SetWindowPos`，把刚隐藏的窗口又显示了出来；所以全屏时表现为“隐藏 → 5 秒后又冒出来 → 再隐藏”的闪烁（之前排查时只看了 hide 日志，没检查窗口实际可见性，所以没发现）；
2. **修复**：`ensure_taskbar_position` 与 `apply_taskbar_mode` 增加保护——全屏隐藏 / 用户手动隐藏期间直接返回，不再调用置顶/重排；
3. 真机验证（B 站客户端全屏窗口保持打开）：v1.2.7 启动后 2 秒内隐藏，随后 4 秒、24 秒两次检查窗口 `IsWindowVisible=False`，不再被 5 秒重排重新显示；日志也不再反复出现“隐藏/恢复”；
4. 版本号 → 1.2.7；已发布 GitHub Release：
   <https://github.com/luongthimydieu/win11-taskbar-lyrics/releases/tag/v1.2.7>。

## v1.2.4（2026-10-17）

修复 v1.2.3 反馈的“任务栏组件一直闪烁”：

1. **根因**：`ensure_taskbar_position` 每 5 秒比较“系统暗色模式”与窗口缓存时，两边取值来源不同（一个是注册表/系统主题，一个是背景采样），导致每隔 5 秒误判为“主题变了”，触发一次重新贴合——把窗口临时移出屏幕再放回，看起来就是一直闪烁；
2. **修复**：主题变化只更新缓存/重绘，**不再触发重新排版**；
3. **全屏检测加防抖**：连续 2 秒检测到全屏才隐藏，连续 3 秒不是全屏才恢复，避免全屏切换瞬间的窗口变化造成闪一下；
4. 真机验证：源码版连续运行 45 秒，日志只有启动时 1 次贴合，不再出现每 5 秒的“任务栏布局变化/重新扫描”；
5. 版本号 → 1.2.4；已发布 GitHub Release：
   <https://github.com/luongthimydieu/win11-taskbar-lyrics/releases/tag/v1.2.4>。

## v1.2.0（2026-10-17）

用户实际使用 v1.1 后反馈了三个体验问题，v1.2 针对性重做：

1. **真正融入任务栏，不再是桌面悬浮卡片**
   - 原来只是 `WindowStaysOnTopHint` 的悬浮窗口，看起来“浮在整个桌面上”；
   - 现在用 Win32 `SetParent` 把自绘窗口挂成 `Shell_TrayWnd` 的子窗口，并加 `WS_CHILD` / `WS_EX_NOACTIVATE`、顶到任务栏子窗口 z 序最前，文字**直接绘制在任务栏表面**（嵌入模式不画任何背景）；
   - 自动扫描任务栏空位（GDI 截一条像素带做图标检测），避开任务栏图标与托盘区；支持拖拽后记住相对位置；
   - 任务栏背景是亚克力、颜色随壁纸变化，所以用像素采样决定文字用深色还是浅色；到点提醒时画红底呼吸；
   - 嵌入失败（例如程序以管理员运行、被 UIPI 限制）自动退回“置顶覆盖”模式，右键菜单可手动切换「嵌入任务栏 / 置顶覆盖 / 自动吸附到空位」；
   - 每 5 秒检测任务栏句柄/矩形变化与嵌入关系，explorer 重启、换分辨率、切主题都会自动重新贴合；
   - 新增 `desktop/diagnose_taskbar.py` 与 `--diagnose`、右键「🩺 任务栏诊断」，输出 Windows 版本、任务栏句柄、嵌入状态、子窗口结构，便于远程排查。

2. **热评只显示“有意思”的那些**
   - 原来直接取 `hotComments` 前 15 条，常出现“好听”“打卡”“前排”等水评或广告；
   - 现在 `core.score_interesting_comment()` 过滤：纯水评、纯表情、广告/引流/联系方式、过短/过长、重复字符；
   - 打分偏好“有故事/有情绪”的短评（那年、毕业、暗恋、深夜、车站、耳机…），并按点赞数温和加权；
   - 单曲只保留约 10 条精选，轮播间隔从 10 秒改为 20 秒（`comment_rotate_sec`），看得完；
   - 好评论不足时退回点赞最高的正常评论，保证有内容可轮播。

## P0-1 数据丢失：整份覆盖 + 无版本校验

### v1.0 的问题

- 手机端 `pushToGist()` 把整个 `todos` 数组 PATCH 上去；
- 电脑端 `mark_todo_done_cloud()` 同样把整个 `todos` 数组 PATCH 上去；
- 两端都没有“先读再合并”，也没有条目级时间戳；
- 结果：
  - 手机离线加了 C，电脑稍后完成 A 并整份写回，C 被覆盖；
  - 手机删了 B，电脑本地仍保留 B，下一轮写回把 B 复活；
  - 两端同时改不同条目，后写者无条件覆盖先写者。

### v1.1 的修复

1. **文档升级到 schema 2**：`schema` / `version` / `updated_at` / `todos` / `tombstones`；
2. **条目级 `updated_at`**：同 id 取时间较新者，整条替换；
3. **删除墓碑**：删除时写 `{id, deleted_at}`，只有 `deleted_at >= updated_at` 才删除，否则视为“删除后又被编辑”而复活；
4. **两端同一套 `mergeDocs`**：Python `core.merge_docs` 与 JS `__TBL_PROTOCOL__.mergeDocs` 逐条对齐；
5. **写前 GET + 合并**：`GitHubGistStore.sync()` 与手机 `syncNow()` 都执行“拉取 → 合并 → 判断 → 按需 PATCH”，不再直接覆盖；
6. **只推本地新增**：`needsPush(local, remote)` 用内容指纹判断，没新内容不写；
7. **ETag 条件请求**：带 `If-None-Match`，304 不计入限流额度；冷启动 304 无缓存时强制全量 GET 一次；
8. **墓碑裁剪**：180 天 / 最多 200 条，避免 Gist 无限膨胀。

### 影响文件

- `desktop/core.py`：`normalize_todo`、`normalize_doc`、`canonical`、`merge_docs`、`needs_push`、`delete_todo`、`GitHubGistStore`
- `desktop/taskbar_widget.py`：`request_sync`、`_sync_worker`、`on_sync_finished`、`_persist_and_sync`
- `github-pages/index.html`：`__TBL_PROTOCOL__`、`syncNow`、`getRemote` / `putRemote` / `createGist`

### 验证

- Python `MergeTests`：远端/本地较新胜、并集、墓碑删除、编辑复活、幂等、`version+1`、`needsPush`；
- Python `GistStoreTests`：304、401、缺文件、推送/不推送、创建 Gist；
- Node `[2] 合并协议` 全部用例；
- 手工场景：手机离线加一条 → 电脑完成另一条 → 手机恢复同步 → 两条都在；手机删除一条 → 电脑同步 → 不复活。

## P0-2 提醒不可靠：只随拉取检查、内存去重、字符串比较

### v1.0 的问题

| 问题 | 代码表现 | 后果 |
| --- | --- | --- |
| 只在拉取成功时检查 | `on_todos_updated()` 里才调用 `check_due_reminders()` | 断网/401/403 时永远不提醒；电脑启动后要先等一次同步 |
| 去重只在内存 | `self.reminded_ids = set()` | 重启程序后同一条再提醒一次 |
| 用 `HH:MM` 字符串比较 | `if remind_at <= now_hm` | “明天 09:00”在今晚 20:00 就被判定到点，立刻弹提醒 |
| 没有日期字段 | 手机端只有 `<input type="time">` | 无法表达“明天/后天” |
| 无云端已提醒状态 | 没有 `notified_at` | 换一台电脑会重复提醒 |
| 无稍后提醒 | 只有“点完成” | 当下不方便时只能完成或忽略 |

### v1.1 的修复

1. **`remind_date` + `remind_at`**：日期与时刻分开存，旧数据无 `remind_date` 时按 `created_at` 当天解释；
2. **`reminder_datetime()`**：把两者组合成本地时区的目标时刻；
3. **24 小时补提醒窗口**：`0 <= now - target <= 86400` 才提醒；关机一晚第二天仍补一次，超过 24 小时不打扰；
4. **`notified_at` 云端去重**：触发时先写本地并尝试同步；另一台电脑看到非空就不再提醒；重启也不重复；
5. **独立 1 秒提醒计时器**：`remind_timer` 与同步解耦，断网也能按时提醒；
6. **提醒队列**：同一时刻多条到期逐条展示，支持完成/稍后/忽略；
7. **稍后提醒**：`snooze_todo()` 把时间改到 now+10 分钟、清空 `notified_at`，跨午夜会改 `remind_date`；
8. **完成/取消完成的语义**：完成写 `done_at`；取消完成清空 `done_at` 与 `notified_at`，允许再次提醒。

### 影响文件

- `desktop/core.py`：`reminder_datetime`、`reminder_delta_seconds`、`due_reminder`、`upcoming_reminders`、`format_reminder`、`snooze_todo`、`mark_notified`
- `desktop/taskbar_widget.py`：`remind_timer`、`check_reminders`、`_activate_next_alert`、`complete_alert`、`snooze_alert`、`dismiss_alert`
- `github-pages/index.html`：`remind_date`、`reminderDatetime`、`dueReminder`、`formatReminder`、编辑弹层的日期/时间

### 验证

- Python `ReminderTests`：显式日期、旧数据按创建日、未到点、到点、24h 窗口内/外、已提醒/已完成、今天/明天标签、多条的到期排序；
- Node `[3] 提醒与排序`：`pendingTodos`、`formatReminder`、`dueReminder`、完成/取消；
- 手工场景：设“明天 09:00” → 今天不提醒；把系统时间调到明天 09:01 → 30 秒内闪烁；重启程序 → 不重复；点「10 分钟后再提醒」→ 10 分钟后再次闪烁。

**已知边界**：仅修改 `remind_at` / `remind_date` 不会自动清空 `notified_at`，已提醒过的条目改时间后不会再次提醒；需要重新提醒时先把该条标记完成、再取消完成（会清空 `notified_at`），或用提醒弹出时的「10 分钟后再提醒」。详见 [03 同步协议](03-同步协议.md#113-notified_at-的写入与清空)。

## P1-1 SMTC：主线程反复 `asyncio.run()`

### v1.0 的问题

## P1-3 任务栏：绝对像素、无 DPI、无重吸附、无单实例/托盘/日志

### v1.0 的问题

7. **滚动日志**：`%APPDATA%\Win11TaskbarLyrics\app.log`，2MB × 3；
8. **配置/状态迁移到 `%APPDATA%`**：`config.json`、`state.json`，原子写（`.tmp` + `os.replace`）；

## P2-1 手机端：从普通网页升级为 PWA

### v1.0 的问题

| 问题 | 表现 |
| --- | --- |
| 不是 PWA | 没有 manifest / service worker / 主屏幕图标，不能像 App 一样打开 |
| 只拉一次 | `loadLocalConfig()` 时 `fetchFromGist()`，之后不自动刷新 |
| 无编辑 | 只能新增/完成/删除，改内容要删了重加 |
| 无清除已完成 | 已完成条目只能逐条删 |
| 错误提示笼统 | 所有失败都是「云端拉取失败」「同步失败」，分不清 401/403/404/网络 |
| 离线改动不重试 | `pushToGist()` 失败只提示，下一次操作才可能再推 |
| 无 dirty 标记 | 页面关闭后不知道还有没有未推送内容 |
| 旧数据兼容弱 | 只认 `local_todos` 数组；没有 `remind_date` |

### v1.1 的改进

1. **PWA**：
   - `manifest.webmanifest`：名称、standalone、主题色、192/512/maskable 图标；
   - `sw.js`：安装时缓存应用外壳，网络优先、离线回退；跨域 GitHub API 永不缓存；
   - `apple-touch-icon.png` 适配 iOS 主屏幕；
   - `index.html` 注册 Service Worker。
2. **自动同步**：启动、60 秒定时、`visibilitychange` 回到前台、`focus`、`online` 网络恢复、本地改动后 900ms 防抖。
3. **编辑弹层**：内容、日期（今天/明天/不提醒）、时间、优先级；保存走 `updateTodo`。
4. **清除已完成**：批量删除，每条写墓碑。
5. **错误分类**：401/403/404/缺失文件/截断/JSON 损坏/网络分别提示；状态点变红。
6. **dirty 与重试**：本地改动写 `tbl.meta.v2` 的 `dirty`；成功后清除；失败保留；`pendingSync` 保证同步中再次触发不会丢。
7. **v1 兼容**：
   - 配置兼容 `gh_token` / `gh_gist_id`；
   - 数据兼容 `local_todos` + `remind_time`；
   - 同时把新配置镜像写回旧键，避免回退版本读不到。
8. **UI**：深色卡片、状态胶囊、筛选标签、空状态、Toast、安全区适配。

- `github-pages/index.html`（协议 + 应用层 + 渲染）
- `github-pages/manifest.webmanifest`、`github-pages/sw.js`
- `github-pages/icon-192.png`、`icon-512.png`、`apple-touch-icon.png`、`.nojekyll`

## 协议与数据迁移

| 项 | v1.0 | v1.1 | 是否自动迁移 |
| --- | --- | --- | --- |
| Gist 文件名 | `taskbar_todos.json` | 同名 | 是，无需改 |
| 顶层结构 | `{updated_at, todos}` | `{schema, version, updated_at, todos, tombstones}` | 是，读取时归一化 |
| 条目提醒 | `remind_time`（仅 HH:MM） | `remind_at` + `remind_date` | 是，`remind_time` → `remind_at`；日期缺失按创建日 |
| 条目时间 | 可能没有 `createdAt`/`updatedAt` | `created_at`/`updated_at` | 缺失补 epoch/当前值 |
| 删除 | 直接移除 | 移除 + 墓碑 | 否，旧删除没有墓碑可补 |
| 手机缓存 | `gh_token` / `gh_gist_id` / `local_todos` | `tbl.*.v2` + 镜像旧键 | 是，首次读取兼容 |
| 电脑配置 | `~/.win11_taskbar_lyrics_todo.json` | `%APPDATA%\Win11TaskbarLyrics\config.json` | **否**，需要重新填 Token/Gist ID |

补充：如果 v1 条目连 `created_at` 都没有，归一化会填 `1970-01-01`；没有 `remind_date` 的旧提醒会因锚点过期而不再触发，升级后需要重新设置提醒日期。

## 升级注意事项

1. **两端一起升级**。v1.0 不认识 `tombstones`，只要它再保存一次，就可能把 v1.1 写入的删除记录抹掉。升级顺序建议：先手机端（只读不写也能显示），再电脑端；升级期间不要在两台设备上同时删改。
2. **先备份 Gist**。打开 Gist → `taskbar_todos.json` → Raw/Download 保存一份；升级后第一次实际推送（新增/编辑/完成/删除）会重写文件（加 `schema`/`version`/`tombstones`），只打开页面或只同步不会改写。
3. **电脑端配置需要重填**。v1.1 不再读用户主目录的旧 dotfile；启动后右键 →「配置 GitHub Gist 云同步」，填同一组 Token + Gist ID。
4. **手机端不用重新建 Gist**。继续用原来的 Gist ID；页面首次加载会在内存中归一化 v1 数据，成功同步或下一次本地变更后才写入 localStorage，云端文件要到实际推送才变成 v2。
5. **不要把 v1.0 留作回退方案**。v1.0 能读 v1.1 的 `todos`（忽略墓碑），但删除/完成状态的同步会退化；回退前先备份，且两端一起回退。
6. **打包版要重新打包**。`build_exe.ps1` 重新生成 `dist`；开机自启快捷方式指向同一路径时无需改，路径变了要用 `-ExePath` 重新注册。
7. **升级后验证**：
   - `python desktop\taskbar_widget.py --selftest` 输出 `SELFTEST OK`；
   - 设置对话框「测试连接」显示云端条数；
   - 手机加一条 → 电脑 30 秒内出现；电脑完成 → 手机回前台变已完成；
   - 删除一条 → 两端等一轮都不再出现；云端 JSON 里有对应墓碑。
