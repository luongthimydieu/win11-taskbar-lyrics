# 06 打包与开机自启

本文只讲两件事：怎么把 `desktop/` 打成独立 exe，怎么让它登录 Windows 后自动出现在任务栏。两条脚本都可以直接运行，不需要管理员权限。

相关文档：[部署指南](02-部署指南.md)、[常见问题](04-常见问题.md)、[更新日志](05-更新日志.md)。

## 1. 什么时候需要打包

| 场景 | 建议 |
| --- | --- |
| 自己电脑长期用，已装 Anaconda | 源码 + `install_autostart.ps1` 即可，改代码方便 |
| 不想每次看到黑色控制台 | 用 `pythonw.exe` 或打包 exe |
| 换电脑/给朋友用，不想装 Python | 打包 exe（onedir 或 onefile） |
| 开机自启且要求启动快 | **onedir** + exe，或 pythonw |
| 只拷一个文件走 | onefile，接受首次启动慢 |

打包前先确认源码能跑：

```bat
cd /d "G:\deepseek harness\win11-taskbar-lyrics"
python desktop\taskbar_widget.py --selftest
```

必须看到 `SELFTEST OK`，并记下 `MEDIA_BACKEND=` 的值；打包后要拿它对照。

## 2. `build_exe.ps1` 用法

### 2.1 基本命令

在 **PowerShell** 中（不是 CMD）：

```powershell
powershell -ExecutionPolicy Bypass -File "G:\deepseek harness\win11-taskbar-lyrics\desktop\build_exe.ps1"
```

默认生成 **onedir**。脚本自己会 `Set-Location` 到 `desktop/`，所以在哪个目录执行都可以。

指定 Python 解释器（推荐，避免 `python` 不在 PATH 或指错环境）：

```powershell
powershell -ExecutionPolicy Bypass -File "G:\deepseek harness\win11-taskbar-lyrics\desktop\build_exe.ps1" -Python "D:\APP\Anaconda\envs\taskbar-lyrics\python.exe"
```

单文件：

```powershell
powershell -ExecutionPolicy Bypass -File "G:\deepseek harness\win11-taskbar-lyrics\desktop\build_exe.ps1" -OneFile
```

### 2.2 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-Python` | `python` | 用来装依赖和打包的解释器；建议写 `python.exe` 全路径 |
| `-OneFile` | 关（onedir） | 加了这个开关才用 `--onefile` |

没有 `-Console`、`-Icon` 等参数；脚本固定 `--windowed`，exe 没有控制台窗口，exe 图标也是 PyInstaller 默认图标。

### 2.3 脚本做了什么

1. `& $Python -m pip install -r requirements.txt`：按当前 Python 版本装 PyQt6 / requests / winsdk 或 pywinrt；
2. `& $Python -m pip install --upgrade pyinstaller`：装/升级 PyInstaller；
3. 组装 PyInstaller 参数：
   - `--noconfirm --clean`：覆盖旧产物、清缓存；
   - `--windowed`：不显示控制台；
   - `--name Win11TaskbarLyrics`：产物名；
   - `--collect-submodules PyQt6.QtCore`：收集 QtCore 子模块；
   - `--onedir`（默认）或 `--onefile`（`-OneFile`）；
   - 检测当前环境有没有 `winsdk`，有就 `--collect-all winsdk`；
   - 检测有没有 `winrt`，有就 `--collect-all winrt`；
4. 执行 `python -m PyInstaller ... taskbar_widget.py`；
5. 打印输出路径和对应的开机自启命令。

`--collect-all` 很关键：`winsdk` / `winrt` 带原生 DLL 和子模块，只靠静态分析容易漏，漏了打包后就会退化成窗口标题兜底。

### 2.4 输出路径

默认 onedir：

```text
G:\deepseek harness\win11-taskbar-lyrics\desktop\dist\Win11TaskbarLyrics\
├── Win11TaskbarLyrics.exe
└── _internal\...            # Qt、Python、媒体后端等依赖
```

`-OneFile`：

```text
G:\deepseek harness\win11-taskbar-lyrics\desktop\dist\Win11TaskbarLyrics.exe
```

构建中间产物：

```text
desktop\build\Win11TaskbarLyrics\
desktop\Win11TaskbarLyrics.spec
```

这些目录已被 `.gitignore` 忽略（`dist/`、`build/`、`*.spec`），不要提交。

## 3. onedir 与 onefile 的取舍

| 维度 | onedir（默认） | onefile（`-OneFile`） |
| --- | --- | --- |
| 启动速度 | 快，直接加载目录里的文件 | 慢：每次启动先把内容解压到 `%TEMP%\_MEI...`，脚本注释给的量级是 5–10 秒 |
| 文件数量 | 一个目录，含 `_internal` | 单个 exe，便于拷贝 |
| 杀软误报 | 相对少 | 相对多，解压行为容易被启发式扫描 |
| 缺 DLL 排查 | 能直接看到 `_internal` 里的文件 | 全打包在 exe 里，排查困难 |
| 适合开机自启 | **推荐** | 不推荐，登录后要等解压 |
| 移动/改名 | 整个目录一起移动；只移 exe 会找不到 `_internal` | 单文件随便移 |
| 更新 | 替换整个目录 | 替换 exe |

任务栏组件是常驻程序，**优先 onedir**；只有“必须单文件分发”时才用 onefile。

## 4. 打包后验证

### 4.1 先跑自检

`--windowed` 的 exe 没有控制台，`print` 的内容看不到，所以用退出码 + 日志验证：

```powershell
$exe = "G:\deepseek harness\win11-taskbar-lyrics\desktop\dist\Win11TaskbarLyrics\Win11TaskbarLyrics.exe"
$p = Start-Process -FilePath $exe -ArgumentList "--selftest" -Wait -PassThru
$p.ExitCode
```

预期输出 `0`。若为 `1`，说明 Qt 启动或自检失败。

再看日志里的后端：

```powershell
Get-Content "$env:APPDATA\Win11TaskbarLyrics\app.log" -Tail 20 | Select-String "启动|媒体后端"
```

应看到类似：

```text
2026-10-17 ... [INFO] taskbar.widget: 启动 Win11TaskbarLyrics v1.1.0，媒体后端=winsdk
```

- `winsdk` / `pywinrt`：正常；
- `无`：打包时没收集到媒体后端，按第 7.6 节处理；
- 没有这行：exe 可能没真正启动，检查 `$p.ExitCode` 和 Windows 事件查看器。

### 4.2 正常启动

```powershell
Start-Process -FilePath "G:\deepseek harness\win11-taskbar-lyrics\desktop\dist\Win11TaskbarLyrics\Win11TaskbarLyrics.exe"
```

检查：

- 任务栏出现胶囊；
- 右键 →「关于」显示版本、媒体后端、配置目录、日志路径；
- 托盘图标可用；
- 桌面端配置（Token/Gist）如果之前填过，会从 `%APPDATA%` 读取，不需要重填；
- 单实例：再启动一次 exe，应弹「程序已经在运行了」。

## 5. `install_autostart.ps1` 用法

### 5.1 源码方式（默认 pythonw，静默启动）

在 **Anaconda Prompt** 或已把目标 Python 放进 PATH 的 PowerShell 中：

```powershell
powershell -ExecutionPolicy Bypass -File "G:\deepseek harness\win11-taskbar-lyrics\desktop\install_autostart.ps1"
```

如果 `python` 不在 PATH，或要指定 conda 环境：

```powershell
powershell -ExecutionPolicy Bypass -File "G:\deepseek harness\win11-taskbar-lyrics\desktop\install_autostart.ps1" -Python "D:\APP\Anaconda\envs\taskbar-lyrics\python.exe"
```

脚本会用该解释器同目录的 `pythonw.exe` 启动 `taskbar_widget.py`，所以**不会**出现黑色控制台窗口。如果该环境没有 `pythonw.exe`（少数精简环境），脚本会报找不到，改用 `-ExePath` 指向打包后的 exe。

### 5.2 exe 方式

```powershell
powershell -ExecutionPolicy Bypass -File "G:\deepseek harness\win11-taskbar-lyrics\desktop\install_autostart.ps1" -ExePath "G:\deepseek harness\win11-taskbar-lyrics\desktop\dist\Win11TaskbarLyrics\Win11TaskbarLyrics.exe"
```

onedir 必须指向目录里的 exe，不能只把 exe 拷到别处；onefile 指向单个 exe 即可。

### 5.3 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-Python` | `python` | 找同目录 `pythonw.exe`；仅在不用 `-ExePath` 时生效 |
| `-ExePath` | 空 | 指向打包后的 exe；给了它就不走 pythonw |
| `-Uninstall` | 关 | 删除启动文件夹里的快捷方式，然后退出 |

### 5.4 卸载

```powershell
powershell -ExecutionPolicy Bypass -File "G:\deepseek harness\win11-taskbar-lyrics\desktop\install_autostart.ps1" -Uninstall
```

只删除快捷方式，不会结束正在运行的程序；先退出程序再卸载。

### 5.5 验证快捷方式

```powershell
explorer "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup"
```

应看到 `Win11 任务栏歌词.lnk`。右键 → 属性，确认：

- **目标**：`pythonw.exe` 或 `Win11TaskbarLyrics.exe`；
- **起始位置**：`...\win11-taskbar-lyrics\desktop`；
- **运行方式**：最小化（脚本设置 `WindowStyle = 7`）。

最可靠的验证是**注销再登录**：胶囊自动出现，且没有控制台窗口。

## 6. 开机自启原理

脚本用的是**当前用户的启动文件夹快捷方式**，不是注册表 `Run`，也不是 Windows 服务：

```text
用户登录
  └─ Explorer 读取：
       %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\Win11 任务栏歌词.lnk
       └─ 目标：pythonw.exe "…\desktop\taskbar_widget.py"
          或：Win11TaskbarLyrics.exe
          工作目录：…\desktop
          └─ Qt 应用启动
              ├─ 单实例互斥量检查
              ├─ 读取 %APPDATA%\Win11TaskbarLyrics\config.json
              ├─ 吸附主任务栏
              └─ 约 1.2 秒后首次同步，之后每 30 秒一次
```

特点：

| 特点 | 说明 |
| --- | --- |
| 不需要管理员 | 启动文件夹属于当前用户，写入不需要提权 |
| 只对当前用户生效 | 换 Windows 用户要重新安装 |
| 登录后启动，不是开机即启动 | 必须等用户登录、Explorer 起来 |
| 可被任务管理器禁用 | 「启动」选项卡里禁用后，快捷方式还在但不会运行 |
| 路径依赖 | 移动项目目录、删 conda 环境、移动 exe 目录都会让快捷方式失效 |
| 不是系统服务 | 只是当前用户登录后启动的普通程序，退出不影响系统 |
| 单实例保护 | 自启 + 手动启动时，第二个实例提示后退出，不会出现两个胶囊 |

如果登录后没有自动出现：

1. 打开 `shell:startup`（Win+R 输入）确认快捷方式在；
2. 任务管理器 →「启动」→ 看 `Win11 任务栏歌词` 是否被禁用；
3. 双击快捷方式手动试一次，看是否弹错；
4. 检查快捷方式的目标路径是否还存在；
5. 看 `%APPDATA%\Win11TaskbarLyrics\app.log` 有没有启动记录。

## 7. 常见打包问题

### 7.1 启动报 `ModuleNotFoundError` / `Failed to execute script`

**原因**：打包用的 Python 和装依赖的 Python 不是同一个；或动态导入的模块没被 PyInstaller 收集。

**处理**：

1. 用 `-Python` 明确指定解释器，先在该解释器里 `pip install -r requirements.txt`；
2. 确认构建日志里有 `检测到 winsdk/pywinrt`；
3. 看 `desktop\build\Win11TaskbarLyrics\warn-Win11TaskbarLyrics.txt` 里有没有 missing module；
4. 先用源码运行复现，排除代码问题；
5. 仍然缺模块时，在 `build_exe.ps1` 的 PyInstaller 参数里补 `--collect-all <包名>` 后重打（这属于修改构建脚本）。

### 7.2 提示找不到 Qt platform plugin `windows`

**表现**：弹窗 `This application failed to start because no Qt platform plugin could be initialized`，或日志里 `Could not find the Qt platform plugin "windows"`。

**原因**：PyQt6 的平台插件没被收集，或 onedir 目录被拆开移动。

**处理**：

1. 用默认 onedir，别只拷 exe；
2. 确认 `dist\Win11TaskbarLyrics\_internal\PyQt6\Qt6\plugins\platforms\qwindows.dll` 存在；
3. 重新安装 PyQt6 后重打：`python -m pip install --force-reinstall PyQt6`；
4. 检查是否混入了别的 Qt 版本（比如系统里另一个 PyQt5/PySide）；
5. 不要把 `dist` 目录放进带中文/特殊权限的路径再运行，先在本机路径测试。

### 7.3 缺 `VCRUNTIME140.dll` / `api-ms-win-crt-*.dll`

**原因**：目标机器没装 Microsoft Visual C++ 运行库。

**处理**：安装 **Microsoft Visual C++ Redistributable 2015–2022 x64**，重启后重试。打包机上有、目标机没有时最容易出现。

### 7.4 杀毒软件/Windows Defender 误报

**表现**：exe 刚生成就被删、运行被拦截、Defender 报 `Trojan:Win32/Wacatac` 之类。

**原因**：PyInstaller 打包器的自解压/加载行为常被启发式规则误判，onefile 更明显。

**处理**：

1. 优先用 onedir，误报率更低；
2. 把 `dist` 目录加入 Defender 排除项（仅限你信任的自建产物）；
3. 有条件就对 exe 做代码签名，SmartScreen 信誉会逐步建立；
4. 向杀软厂商提交误报样本；
5. 不要为了运行而长期关闭实时保护。

### 7.5 单文件启动很慢

**原因**：onefile 每次启动都会把内嵌文件解压到 `%TEMP%\_MEIxxxx`，再加载 Qt；杀软还会扫描解压出来的文件。

**取舍**：

- 任务栏常驻、开机自启：用 onedir；
- 必须单文件：接受 5–10 秒启动，或改成“首次启动后常驻，不随登录启动”；
- 不要用 onefile + 开机自启，登录后要等解压，体验差。

### 7.6 打包后媒体后端失效（`MEDIA_BACKEND=none` / 日志「媒体后端=无」）

**原因**：

- 构建环境没装 `winsdk` / `winrt`；
- 装了但 PyInstaller 没收集到原生 DLL/子模块；
- 打包后换到另一台机器，目标机缺少对应 VC 运行库；
- 先装 winsdk 后装 pywinrt，构建时两个都收集，运行时优先 winsdk（一般不是问题，但版本可能不匹配）。

**处理**：

1. 在**同一解释器**里确认：

   ```bat
   python -c "import importlib.util as u; print('winsdk', bool(u.find_spec('winsdk')), 'winrt', bool(u.find_spec('winrt')))"
   ```

2. 重新执行 `build_exe.ps1`，看输出里有没有 `检测到 winsdk，打包时一并收集` 或 `检测到 pywinrt(winrt)，打包时一并收集`；
3. 用 `Start-Process ... --selftest` 看退出码，再看日志的 `媒体后端=`；
4. 仍然为「无」：在构建参数里显式 `--collect-all winsdk` / `--collect-all winrt`，或改用源码 + pythonw；
5. 没有媒体后端也能用，只是歌词按窗口标题估算，见 [常见问题](04-常见问题.md#2-媒体后端没生效media_backend-怎么看)。

### 7.7 exe 双击没反应 / 一闪而过

`--windowed` 没有控制台，异常不一定弹窗。排查顺序：

1. `Start-Process ... --selftest -Wait -PassThru` 看退出码；
2. 看 `%APPDATA%\Win11TaskbarLyrics\app.log` 最后 50 行；
3. 用源码 `python desktop\taskbar_widget.py` 复现；
4. 检查是否被单实例锁拦住（已有一个实例在跑）；
5. 检查杀软隔离区；
6. 用 `build\...\warn-*.txt` 看缺失模块。

### 7.8 exe 图标/版本信息不是自己的

脚本没有传 `--icon` 和 `--version-file`，所以 exe 用 PyInstaller 默认图标，属性里也没有版本信息。需要自定义时，在 `build_exe.ps1` 的参数字符串里加 `--icon`、`--version-file` 后重打；这属于修改构建脚本，不在本文档范围内。

### 7.9 打包失败：`pip` 网络错误 / PyInstaller 版本不兼容

- 换国内 pip 源或代理后重试；
- 脚本每次 `--upgrade pyinstaller`，如果新版本与当前 Python/PyQt6 不兼容，在环境里固定一个可用版本后再跑；
- 确认磁盘空间足够（Qt 打包后通常几百 MB）；
- 路径带空格不是问题，脚本内部都用了引号；但过长路径可能触发 Windows 260 字符限制，必要时把项目移到更短的路径。

## 8. 升级、迁移与卸载

### 8.1 升级 exe

1. 退出正在运行的程序（托盘 → 退出）；
2. 重新执行 `build_exe.ps1`；
3. onedir：整个 `dist\Win11TaskbarLyrics` 替换；onefile：替换 `dist\Win11TaskbarLyrics.exe`；
4. 配置和待办不受影响（在 `%APPDATA%` 与云端 Gist）；
5. 开机自启快捷方式指向同一路径时不用重装；路径变了用 `-ExePath` 重新注册。

### 8.2 迁移到另一台电脑

1. 拷 onedir 整个目录，或 onefile 单个 exe；
2. 目标机装 VC++ 运行库；
3. 首次运行后右键配置 Token + Gist ID（配置不随 exe 走）；
4. 需要自启就重新执行 `install_autostart.ps1 -ExePath ...`（启动文件夹是按用户的）。

### 8.3 卸载

```powershell
# 1) 取消开机自启
powershell -ExecutionPolicy Bypass -File "G:\deepseek harness\win11-taskbar-lyrics\desktop\install_autostart.ps1" -Uninstall

# 2) 退出程序后删除打包产物（可选）
Remove-Item -Recurse -Force "G:\deepseek harness\win11-taskbar-lyrics\desktop\dist"
Remove-Item -Recurse -Force "G:\deepseek harness\win11-taskbar-lyrics\desktop\build"
```

如果要连本地配置一起清掉：

```powershell
Remove-Item -Recurse -Force "$env:APPDATA\Win11TaskbarLyrics"
```

云端 Gist 不会受影响；不需要时到 GitHub 删除 Gist。
