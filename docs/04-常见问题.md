# 04 常见问题

先做三件事，大部分问题能在 2 分钟内定位：

1. 跑一次无界面自检：`python desktop\taskbar_widget.py --selftest`，看 `MEDIA_BACKEND=` 和 `SELFTEST OK`；
2. 看日志尾部：`Get-Content "$env:APPDATA\Win11TaskbarLyrics\app.log" -Tail 50`；
3. 打开电脑端设置对话框点「测试连接」，确认 Token + Gist ID 这一层是通的。

如果问题涉及数据，先备份 Gist 里的 `taskbar_todos.json`，再动手。

## 1. 没有歌词，也没有高赞热评

**表现**：胶囊主行只显示 `🎵 歌名 - 歌手`，副行显示「💬 暂无高赞热评」；或者主行一直停在「正在获取歌词与热评…」。

**按顺序排查**：

1. **先确认歌名识别到了**。如果主行连歌名都没有，是媒体后端问题，不是网易云问题，看下一节。
2. **看日志有没有拉取记录**：

   ```powershell
   Get-Content "$env:APPDATA\Win11TaskbarLyrics\app.log" -Tail 80 | Select-String "网易云|歌词|热评"
   ```

   正常会有一行 `拉取网易云数据：歌名 - 歌手`；失败会有 `歌词/热评不可用：…`。
3. **手动验证接口**（在项目根目录、已装 `requests` 的环境）：

   ```bat
   python -c "import sys; sys.path.insert(0,'desktop'); import core; b=core.NetEaseClient().fetch_song_bundle('晴天','周杰伦'); print('ok=',b['ok'],'error=',b['error'],'lyrics=',len(b['lyrics']),'comments=',len(b['hot_comments']))"
   ```

   - `ok= True` 且 `lyrics` 大于 0：接口正常，问题在客户端状态（切歌/重启再试）；
   - `ok= False` 且 `error` 含「未在网易云找到匹配歌曲」：搜索没匹配到，换一个更准确的歌名/歌手，或该歌曲没有版权；
   - 抛 `ConnectionError` / `Timeout`：网络、代理、DNS 或公司防火墙拦截了 `music.163.com`；
   - 返回 `ok= True` 但 `lyrics= 0`：歌曲本身没有 LRC（纯音乐、翻唱、电台）；
   - `comments= 0`：该歌曲没有热评或评论接口返回空，属正常。
4. **接口风控**：短时间频繁切歌可能触发网易云限流，等几分钟再试；程序只缓存成功结果 30 分钟，失败不缓存，但同一首歌失败后不会自动重试，**切歌或重启程序**才会再次请求。
5. **代理/加速器**：部分游戏加速器会劫持 DNS，把 `music.163.com` 指到不可用节点；先关掉再试。

修不好也不影响核心功能：待办、同步、提醒都不依赖网易云接口。

## 2. 媒体后端没生效（`MEDIA_BACKEND` 怎么看）

**表现**：能显示歌名但歌词不跟拍；或者完全识别不到播放；或者 `--selftest` 输出 `MEDIA_BACKEND=none`。

**自检输出**：

```bat
cd /d "G:\deepseek harness\win11-taskbar-lyrics"
python desktop\taskbar_widget.py --selftest
```

```text
MEDIA_BACKEND=winsdk
CONFIG=C:\Users\<你>\AppData\Roaming\Win11TaskbarLyrics\config.json
SELFTEST OK
```

| 输出 | 含义 | 处理 |
| --- | --- | --- |
| `MEDIA_BACKEND=winsdk` | 用的是 `winsdk` 后端 | 正常（Python ≤3.11） |
| `MEDIA_BACKEND=pywinrt` | 用的是 `winrt-Windows.Media.Control` 拆分包 | 正常（Python 3.12+） |
| `MEDIA_BACKEND=none` | 两个后端都没导入成功 | 按下面的命令重装，注意装到**运行程序的那个 Python** |

**确认装到了哪个环境**：

```bat
where python
python -c "import sys; print(sys.executable)"
python -c "import importlib.util as u; print('winsdk', bool(u.find_spec('winsdk')), 'winrt', bool(u.find_spec('winrt')))"
```

- Python 3.11 路线（本项目专用环境 `taskbar-lyrics` 已装好）：

  ```bat
  conda activate taskbar-lyrics
  python -c "import requests, winsdk; from winsdk.windows.media.control import GlobalSystemMediaTransportControlsSessionManager as M; print('OK')"
  ```

- Python 3.13 路线：

  ```bat
  python -m pip install PyQt6 requests "winrt-Windows.Media.Control>=3.2.1"
  python -c "from winrt.windows.media.control import GlobalSystemMediaTransportControlsSessionManager as M; print('OK')"
  ```

**常见原因**：

- `pip install` 装到了 base，程序却跑在 `taskbar-lyrics`（或反过来）。用 `sys.executable` 确认；
- 同时装了 `winsdk` 和 `winrt`：代码优先 `winsdk`，想看 pywinrt 效果要先卸掉 winsdk；
- 在普通 PowerShell 里跑 `python`，命中 Microsoft Store 的假 python 或另一个解释器；用 Anaconda Prompt；
- Python 3.12/3.13 上强行 `pip install winsdk`：没有对应轮子，报 `no matching distribution`，改用 pywinrt。

程序「关于」对话框也会显示当前后端（`媒体后端：winsdk` / `pywinrt` / `窗口标题兜底`）。

## 3. 暂停后歌词还在滚

**原因**：当前走的是**窗口标题兜底**（`MEDIA_BACKEND=none`，或 SMTC 没读到网易云会话）。兜底模式只能拿到「歌名 - 歌手」，拿不到播放进度，也判断不了暂停；代码按单调时钟持续外推，所以暂停后仍然前进。

**确认**：

- 看「关于」对话框或 `--selftest` 的 `MEDIA_BACKEND`；
- 日志启动行：`启动 Win11TaskbarLyrics v1.1.0，媒体后端=...`。

**解决**：

1. 按上一节装好 `winsdk` 或 `pywinrt`，重启程序；
2. 确认网易云 PC 端正在使用支持 SMTC 的版本（Windows 媒体控件里能看到它）；
3. 按键盘媒体键（或打开快速设置里的媒体控件），确认系统能读到网易云会话；读不到就重启网易云；
4. 有 SMTC 后，`is_playing` 为 false 时歌词会冻结在当前位置，拖动进度条也会在 2 秒内回填。

**已知边界**：即使有 SMTC，进度锚点每 2 秒才更新一次，暂停瞬间最多有约 2 秒的视觉滞后；这属于正常。

## 4. 任务栏位置不对 / 多屏 / DPI / 任务栏自动隐藏

**定位逻辑**：程序只读取**主任务栏** `Shell_TrayWnd` 的物理像素矩形，按主屏 `devicePixelRatio` 换算成 Qt 逻辑像素，再用 `offset_ratio`（相对任务栏宽度的比例，默认 0.24）算 x，垂直居中。

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 换了分辨率/缩放后跑到屏幕外 | 旧版用绝对像素；v1.1 已改相对比例 | 右键「📌 重新对齐任务栏」；还不对就拖动一次，松手会保存新比例 |
| 拖到一半位置没记住 | 配置只在**松手**时写 | 拖到目标位置后松开左键，再重启验证 |
| 多屏时只在主屏 | 只枚举主任务栏 | 把胶囊拖到主屏任务栏；副屏任务栏不支持 |
| 任务栏在屏幕顶部 | 代码按任务栏矩形居中，顶部也能放 | 仍可能被窗口按钮挡住；换位置或关闭「任务栏居中」 |
| 任务栏在屏幕左侧/右侧（竖排） | 没有为竖向任务栏做布局 | 不支持；请把任务栏放回底部 |
| 任务栏自动隐藏 | 隐藏时 `Shell_TrayWnd` 矩形可能只剩一条边或移出屏幕 | 关闭自动隐藏，或唤出任务栏后点「重新对齐」 |
| 缩放 125%/150% 后偏一点 | 物理↔逻辑换算有 1–2 px 误差，多屏不同缩放更明显 | 把主屏缩放设为整数（100%/200%），或手动拖一次 |
| 被开始按钮/搜索框挡住 | 比例位置正好落在系统按钮上 | 拖到任务栏空白段，松手保存 |

**验证**：

```powershell
Get-Content "$env:APPDATA\Win11TaskbarLyrics\app.log" -Tail 30 | Select-String "任务栏几何"
```

任务栏矩形变化时日志会打印 `检测到任务栏几何变化，重新吸附：(left, top, width, height)`。

## 5. 胶囊被全屏程序遮挡

`WindowStaysOnTopHint` 只能压住普通窗口，压不住：

- 独占全屏的 DirectX 游戏；
- 部分播放器的全屏独占模式；
- UAC 安全桌面、锁屏、任务视图；
- 某些带反作弊/覆盖层保护的程序。

**处理**：

1. 游戏/播放器改成「无边框窗口化」或「窗口化全屏」；
2. 退出全屏后胶囊会自动回到任务栏上方；
3. 不要试图用「始终置顶」对抗独占全屏，这是 Windows 的显示层级限制，不是程序 bug。

## 6. explorer 重启后胶囊位置不对

Windows 重启 `explorer.exe`（安装软件、更新、崩溃恢复时常见）会销毁并重建任务栏。程序每 **5 秒**检测一次任务栏矩形，发现变化且不在拖拽中，就重新吸附。

**现象与处理**：

- 胶囊短暂错位，几秒后自己回来：正常；
- 一直不回来：右键「📌 重新对齐任务栏」；仍不行就退出程序重开；
- 托盘图标消失：任务栏重建可能影响托盘注册，通常几秒内恢复；一直不回来就重启程序（胶囊本身不受影响）；
- 不要同时开两个实例试图“修复”，第二个会被单实例锁拦下。

## 7. 点了完成，手机端没同步

电脑端点击完成后会**先改本地并立即写 `state.json`**，再异步 PATCH；所以即使同步失败，本机不会丢这次完成。手机端没变化，通常是同步层出错。

**先看错误属于哪一类**（设置对话框「测试连接」或日志）：

| 现象/日志 | 含义 | 处理 |
| --- | --- | --- |
| `401` / `Token 无效或已过期` | Token 错、过期、被撤销 | 重新生成 classic token（只勾 `gist`），手机和电脑都更新 |
| `403` / `拒绝访问` | 没勾 `gist`；或触发限流 | 检查 Token scopes；等限流窗口（见第 14 节） |
| `404` / `Gist 不存在` | Gist ID 错、Gist 被删、Token 无权访问 | 核对 ID；用「创建新 Gist」重建并让两端换 ID |
| `网络错误：…` / `Failed to fetch` | 断网、代理、DNS、证书 | 恢复网络后下一轮自动重试 |
| `Gist 中的 JSON 解析失败` / `内容被截断` | 云端文件坏了或超过 1MB | 先备份，再从 Gist 历史恢复；清理已完成待办 |

**验证是否真的写回**：

1. 打开 Gist 页面，点 `taskbar_todos.json`，搜该条目的 `"done": true` 和 `done_at`；
2. 电脑端托盘悬停，应显示「最近同步 HH:MM」；
3. 手机端回到前台（或下拉刷新/重新打开），触发一次 `syncNow`；
4. 若云端已是 `done: true` 但手机没变，是手机端缓存/网络问题：强制关闭页面重开，或清除站点数据后重新填 Token/Gist ID。

**修好 Token 后本地改动会不会补推？** 会。`state.json` 里保留了本地文档，下一次成功同步时 `merge_docs` 会让较新的 `done` 胜出，`needsPush` 为真后 PATCH。

## 8. 手机端打开空白 / 离线打不开

### 8.1 空白或 404

1. 确认 Pages 已发布：仓库 **Settings → Pages** 顶部应有绿色站点地址；刚开启要等 1–2 分钟；
2. 地址必须是 `https://<用户名>.github.io/<仓库名>/`，注意末尾斜杠和仓库名大小写；
3. 私密仓库的 Pages 需要付费套餐；免费账号请用公开仓库；
4. 确认 `index.html` 在仓库**根目录**，不是 `github-pages/index.html` 这种多一层；若放在子目录，地址要带子目录；
5. 强制刷新：iOS Safari 关闭标签页重开；Android Chrome 菜单 → 刷新；仍旧就清除站点数据；
6. 看浏览器控制台（桌面 Chrome 远程调试）是否有 JS 报错或 404 资源。

### 8.2 离线

- Service Worker 只缓存**应用外壳**（`index.html`、manifest、图标），所以断网时页面还能打开；
- 数据来自 `localStorage` 缓存，能看、能改；改动会打上 `dirty` 标记；
- GitHub API 跨域请求**不走缓存**，离线时同步失败是预期行为；
- 恢复网络、页面回到前台、窗口聚焦时，`syncNow` 会自动重试；`dirty` 为真会强制推送；
- 离线期间不要清除站点数据，否则未推送的改动会丢。

**验证 Service Worker**：Chrome DevTools → Application → Service Workers，应看到 `sw.js` 为 activated；Cache Storage 里有 `tbl-shell-v2`。

## 9. Token 泄露了怎么办

1. 立刻打开 GitHub → **Settings → Developer settings → Personal access tokens → Tokens (classic)**；
2. 找到对应 Token，点 **Delete**（或 Revoke）；撤销立即生效，旧 Token 再请求就是 401；
3. 重新生成一个只勾 `gist` 的 Token；
4. 手机端配置面板、电脑端设置对话框都替换成新 Token，各点一次「保存并同步」；
5. 检查 Gist 的 **Revisions** 是否有不认识的改动；必要时删除该 Gist，用「创建新 Gist」重建，并让两端换新 ID；
6. 如果 Token 曾被提交到 Git 仓库：仅删除文件不够，历史里仍能翻到；用 `git filter-repo` 清理历史或直接废弃仓库，并**先撤销 Token**。

补充：

- 只勾 `gist` 的 Token 只能读写你的 Gist，不能碰代码仓库；但仍能读取你所有私密 Gist，所以私密 Gist 不要放敏感信息；Gist 链接泄露时，知道链接的人也可能查看内容。
- 程序不会把 Token 写进日志；排查问题时也不要手动把 `config.json` 或手机 localStorage 截图发出去。

## 10. 删除的待办又出现了

这是同步合并的 normal 行为，不一定是 bug。删除不是“从数组里抹掉”这么简单：如果只是删除，另一端手里的旧副本会在下一轮 merge 时把它加回来。所以 v1.1 用**墓碑**记录删除。

**先判断属于哪种**：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 删除后 30 秒内另一端还显示 | 还没同步到 | 等一轮，或点「立即同步」 |
| 删除后过一轮又回来，云端 JSON 里没有对应墓碑 | 另一端是 v1.0，整份覆盖把墓碑抹了 | 两端都升级到 v1.1；重新删除一次 |
| 云端有条目且 `updated_at` 比墓碑的 `deleted_at` 新 | 删除之后又编辑过，按协议“复活” | 确认是否有人改过；要删就再删一次 |
| 云端有墓碑，但本地仍显示 | 本地还没拉到墓碑，或本地缓存是旧的 | 立即同步；仍不行看日志/清本地缓存 |
| 离线超过 180 天后回来 | 墓碑被 TTL 裁剪 | 重新删除；重要数据不要长期单端离线 |
| 两端时钟差很大 | 旧编辑的 `updated_at` 反而更大，赢了墓碑 | 开启系统自动对时，重新删除 |

**核对云端**：打开 Gist 的 `taskbar_todos.json`，搜索该条 `id`：

- `todos` 里有、`tombstones` 里没有 → 没有删除记录；
- `tombstones` 里有 `{"id": "...", "deleted_at": "..."}` → 删除已记录，比较 `deleted_at` 与条目 `updated_at`；
- 两者都有 → 看时间，`deleted_at >= updated_at` 才会删。

**不要**用“把 todos 数组手工清空”的方式删单条：那不会留下墓碑，另一端的旧副本会把它带回来。正确做法是在手机端点删除（会写墓碑），或手工同时把条目移到 `tombstones`。

## 11. 程序启动了两次 / 出现两个胶囊

程序用 Windows 命名互斥量 `Local\Win11TaskbarLyrics_SingleInstance` 做单实例：

- 第二个实例启动时会弹「程序已经在运行了：请从任务栏胶囊或托盘图标操作」，然后退出（退出码 0）；
- 开机自启 + 手动再启动一次，也会走这个逻辑，不会出现两个胶囊。

**仍看到两个胶囊时**：

1. 打开任务管理器，结束所有 `python.exe` / `pythonw.exe` / `Win11TaskbarLyrics.exe`；
2. 确认没有残留的 `--selftest` 或旧版本进程；
3. 重新启动一个；
4. 如果两个实例来自**不同的 Windows 用户会话**，`Local\` 互斥量按会话隔离，两个用户各有一个是正常的（各自有独立 `%APPDATA%`）。

`--selftest` 不参与单实例检查，它启动 1.5 秒就退出，不会留下界面；不要把它当第二个实例。

## 12. 日志在哪，怎么看

| 文件 | 路径 | 内容 |
| --- | --- | --- |
| 主日志 | `%APPDATA%\Win11TaskbarLyrics\app.log` | 启动、媒体后端、拉取歌词、同步失败、任务栏几何变化 |
| 滚动备份 | 同目录 `app.log.1` ~ `app.log.3` | 每个 2MB，最多 3 个备份 |
| 本地状态 | 同目录 `state.json` | `doc`、`etag`、`last_sync`、`last_error` |
| 配置 | 同目录 `config.json` | Token、Gist ID、位置比例、宽度、模式、同步间隔 |

**PowerShell 实时看**：

```powershell
Get-Content "$env:APPDATA\Win11TaskbarLyrics\app.log" -Tail 50 -Wait
```

**只看错误**：

```powershell
Get-Content "$env:APPDATA\Win11TaskbarLyrics\app.log" -Tail 200 | Select-String "ERROR|WARNING|失败|错误"
```

**打开目录**：右键胶囊 →「🗂️ 打开数据目录」，或：

```powershell
explorer "$env:APPDATA\Win11TaskbarLyrics"
```

日志不含 Token；但会包含歌名、Gist 错误文本、任务栏坐标，发 issue 前可自行删减。

## 13. 怎么彻底重置

### 13.1 只重置电脑端

先退出程序（右键 →「退出程序」或托盘 →「退出」），确认任务管理器里没有残留进程，然后：

```powershell
# 先确认路径就是你要删的那个
$target = Join-Path $env:APPDATA "Win11TaskbarLyrics"
$target
Remove-Item -Recurse -Force $target
```

这会删除配置、本地缓存、日志和 ETag。云端 Gist 不受影响；重启后重新填 Token + Gist ID 即可拉回全部待办。

### 13.2 重置手机端

浏览器设置里清除该 Pages 站点的数据，或在控制台执行：

```javascript
Object.keys(localStorage)
  .filter((key) => key.startsWith('tbl.') || ['gh_token', 'gh_gist_id', 'local_todos'].includes(key))
  .forEach((key) => localStorage.removeItem(key));
location.reload();
```

### 13.3 重置云端

- **清空待办**：手机端点「清除已完成」，或逐条删除（会写墓碑）；也可以直接在 Gist 里把 `todos` 改成 `[]`，但要同时清空/保留合理墓碑，否则旧设备可能复活条目；
- **换新库**：手机端「创建新 Gist」→ 把新 ID 填到电脑端；旧 Gist 可在 GitHub 删除；
- **彻底不要了**：删除 Gist，并取消两台设备的配置；否则仍指向旧 ID 的一端会持续报 404。


## 14. Gist 限流（5000 次/小时）

GitHub 对认证用户的通用限额是 **每小时 5000 次**。本项目的基线消耗：

| 来源 | 次数/小时 | 说明 |
| --- | --- | --- |
| 电脑端 30 秒轮询 | 约 120 | 绝大多数是 304，**304 不计入限额** |
| 手机端 60 秒轮询 | 约 60 | 页面在前台才跑 |
| 手机回前台/聚焦/联网 | 不定 | 每次切回页面可能触发一次 |
| 真正的写入 | 按变更次数 | 每次 PATCH 一次 |
| 手动「立即同步」 | 按点击次数 | 连点会叠加 |

**判断是不是限流**：

```powershell
$env:GH_TOKEN = "ghp_你的Token"
curl.exe -s -H "Authorization: Bearer $env:GH_TOKEN" https://api.github.com/rate_limit
Remove-Item Env:GH_TOKEN
```

看 `resources.core.remaining` 和 `reset`（Unix 时间戳）。注意 403 也可能是**没有 gist 权限**，不一定是限流；两者提示相同，需要看 Token scopes 和响应头 `X-RateLimit-Remaining`。

**处理**：

1. 等到 `reset` 时间后自动恢复；
2. 减少手动同步和多台电脑数量；
3. 确认 ETag 生效：日志里若每轮都是完整 GET（没有 304 分支），检查 `state.json` 的 `etag` 是否为空、手机端是否能读到 `ETag` 响应头；
4. 不要把 `sync_sec` 改得太小（默认 30 秒）；改成 5 秒会显著增加请求量；
5. 403 若伴随 `Retry-After`，按提示等待；程序不自动解析该头。

## 15. 能不能多台电脑共用

可以，前提是**同一组 Token + 同一个 Gist ID**：

- 每台电脑各自 30 秒轮询，按条目合并；A 电脑完成一条，B 电脑下一轮就能看到；
- 每台电脑的窗口位置、显示模式、同步间隔存在各自的 `%APPDATA%\Win11TaskbarLyrics\config.json`，互不影响；
- 单实例锁是**每台机器/每个用户会话**的，不会阻止多台电脑同时运行；
- 手机端可以同时连同一个 Gist。

注意事项：

| 风险 | 说明 | 建议 |
| --- | --- | --- |
| 同一条目同时编辑 | 条目级 LWW，后写胜出，另一边内容被整条覆盖 | 分工编辑不同条目；不要同时改同一条 |
| 时钟偏差 | `updated_at` 来自各机本地时钟，偏差大时旧编辑可能赢 | 所有机器开启自动对时 |
| Token 共享 | 一处泄露/撤销会影响全部机器 | 只勾 `gist`；泄露时全部更新 |
| 限流 | 每台电脑约 120 次/小时（多为 304） | 3–5 台通常无压力；更多就调大 `sync_sec` |
| 版本混用 | 一台 v1.0 会破坏墓碑 | 全部升级到 v1.1 |
| 数据规模 | 多端长期不清理会逼近 1MB | 定期「清除已完成」 |

如果多人共用一个 Gist，注意它**不是**权限隔离的协作空间：所有持有 Token 的人都能读写全部内容。

### 开发中踩过的坑（已修复，仅作排错参考）

v1.1 开发期这个测试出现过一次：

```text
FAIL formatReminder：今天 / 明天
     '今天 09:00' == '明天 09:00'
```

根因不在合并协议，而在**测试辅助函数**：`isoDate(1)` 在 Node 宿主 realm 里创建 `Date`，再传给 `vm` 沙箱里的 `P.toIso()`；`toIso` 内部用 `date instanceof Date` 判断，跨 realm 时构造函数不是同一个，判断为 `false`，于是回退成“当前时间”，`isoDate(1)` 实际返回了今天。

修复方式（已包含在交付版本里）：测试辅助函数改成用本地年月日直接拼日期字符串，不再跨 realm 传 `Date`。浏览器生产路径不受影响（`Date` 与 `toIso` 在同一个 realm）。**以后改测试请记住：不要跨 `vm` 边界传 `Date` 对象**，传时间戳或日期字符串最稳；同时实现侧的 `toIso` 也可以改成鸭子类型判断（`date && typeof date.getFullYear === 'function'`）来彻底避免这类问题。

## 桌面端没显示文字 / 看起来像贴了一块

**先确认数据正常**：打开 `%APPDATA%\Win11TaskbarLyrics\last_text.json`：

- `primary` / `secondary` 里有歌词/热评 → 数据正常，问题在显示层；
- 还停在“正在获取歌词与热评…” → 网络/接口问题，看 `app.log` 里的“拉取网易云数据”和超时提示。

**当前默认是「置顶覆盖」模式**（右键 →「🧲 任务栏集成」可切换）：

1. 窗口用“任务栏背景截图”当底色，看起来和任务栏一致；它不是任务栏子窗口，而是置顶窗口；
2. 如果文字盖住了图标：右键 →「自动吸附到托盘左侧空位」，或左键拖拽后松手保存位置；
3. 如果被别的置顶窗口盖住：右键 →「📌 重新贴合任务栏」或重启程序（程序每 5 秒会自动重新置顶一次）；
4. 如果切到「嵌入任务栏」后文字不刷新/消失：这是跨进程子窗口在部分 Windows 11 版本上的合成限制，切回「置顶覆盖」即可；
5. **打开很多窗口、任务栏按钮变多时**：程序每 5 秒对比开始按钮/任务按钮/托盘的安全区，图标挤过来会自动缩窄并换到新空位；空间完全不够（左/右空档都 < 220px）时会暂时隐藏并在托盘弹提示，关掉一些窗口后自动恢复显示。也可以右键 →「📌 重新贴合任务栏」手动立即重排；
6. 想彻底重置布局：退出程序，删除 `%APPDATA%\Win11TaskbarLyrics\config.json` 后重启（Token/Gist ID 需重填）。

**注意**：覆盖模式下窗口是置顶的，全屏独占游戏会遮住它；任务栏自动隐藏时它不会跟着隐藏（需要隐藏请右键/托盘退出）。

## 每天 22:00 的填写提醒 / 凌晨 2 点“翻篇”是怎么算的

- **22:00 之后添加的待办算“明天”**：手机端或电脑端在 22:00–23:59 新增的待办，归属日期是第二天；0:00–1:59 新增的也算当天（也就是前一晚说的那个“明天”）；
- **0:00–1:59 仍算前一天**，凌晨 2:00 起任务栏才自动切到新的一天，避免半夜提前把昨天的待办切走；
- **每天 22:00** 如果“明天”还没有未完成待办：电脑托盘弹一次提醒，任务栏副行显示「📝 22:00 了，去手机填明天的待办」；手机页面顶部显示提示条；
- **关闭提醒**：右键任务栏组件 →「⏰ 每天 22:00 提醒填待办」取消勾选（手机端提示条是页面本地判断，无法单独关）；
- 22:00 时电脑关机/程序没开也没关系：当天 22:00–01:59 之间启动会补提醒一次，已提醒过则不重复；
- 今天的任务都完成后，如果今天还有逾期项，任务栏会显示「⏰ 逾期：最早那条」，不会当作“今天没有待办”。
