# 02 部署指南

本文从零开始，把手机端、云端 Gist、Windows 任务栏端串起来。每一步都给了**验证方法**，做完一步再进下一步，出问题能立刻定位。

> 本文命令按 Windows 11 编写。项目示例路径为 `G:\deepseek harness\win11-taskbar-lyrics`，路径带空格，命令里都加了引号；换目录时同步替换即可。
>
> 本机实测环境（2026-10）：
>
> - Anaconda base：**Python 3.13.9**，`requests 2.32.5` 已装；`winsdk` 官方没有 cp313 轮子（`pip install winsdk` 报 no matching distribution），但 `winrt-Windows.Media.Control 3.2.1` 有 cp313 轮子。
> - **本项目专用环境 `taskbar-lyrics`（已创建，推荐直接用）**：**Python 3.11.15** + `PyQt6 6.11.0` + `requests 2.34.2` + `winsdk 1.0.0b10`，`conda activate taskbar-lyrics` 即可运行。
> - 原 conda 环境 `wuyijianmo`：**Python 3.11.15**，已装 `PyQt6 6.11.0`，缺 `requests`、`winsdk`；`winsdk==1.0.0b10` 有 cp311 轮子（作为备用路线）。
> - `python` 不在系统 PATH，必须从 **Anaconda Prompt** 启动，或写全路径 `D:\APP\Anaconda\python.exe`。

## 1. 创建 GitHub Token（classic，只勾 gist）

1. 登录 GitHub，点右上角头像 → **Settings**；
2. 左侧最下方 **Developer settings** → **Personal access tokens** → **Tokens (classic)**；
3. 点 **Generate new token (classic)**，可能会要求输入密码/2FA；
4. 填写：
   - **Note**：`win11-taskbar-lyrics`（随便起，便于以后识别）；
   - **Expiration**：按需，建议 90 天；到期前记得换；
   - **Select scopes**：**只勾 `gist`**。不要勾 `repo`、`workflow`、`delete_repo`。
5. 点 **Generate token**，复制 `ghp_...` 开头的字符串。

> Token 只显示一次。不要发到聊天工具、不要提交到 Git。手机端和电脑端填的是**同一个** Token。

**验证 Token 有 gist 权限**（PowerShell，Token 只放进当前会话环境变量）：

```powershell
$env:GH_TOKEN = "ghp_你刚才复制的Token"
curl.exe -s -D - -o NUL -H "Authorization: Bearer $env:GH_TOKEN" "https://api.github.com/gists?per_page=1" | Select-String "HTTP/|x-oauth-scopes"
Remove-Item Env:GH_TOKEN
```

预期看到 `HTTP/2 200`（或 `HTTP/1.1 200`）且 `x-oauth-scopes` 里包含 `gist`。若状态是 `401`，Token 复制错了或已失效；若 scope 里没有 `gist`，回到第 4 步重新勾选权限并生成新 Token。

## 2. 部署手机端到 GitHub Pages

推荐**单独建一个仓库**，只放 `github-pages/` 里的内容；不要把 `desktop/`、`reference/`、`docs/` 一起推上去。

### 2.1 推送文件

在 **Anaconda Prompt / CMD** 中：

```bat
cd /d "G:\deepseek harness\win11-taskbar-lyrics\github-pages"
git init
git add .
git commit -m "feat: 手机端待办同步台（Win11 任务栏组件配套）"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

如果本机没有配置 Git 身份，先执行一次：

```bat
git config --global user.name "<你的名字>"
git config --global user.email "<你的邮箱>"
```

### 2.2 开启 Pages

1. 打开仓库页面 → **Settings** → 左侧 **Pages**；
2. **Source** 选 **Deploy from a branch**；
3. **Branch** 选 **main**，目录选 **/(root)**，点 **Save**；
4. 等 1–2 分钟，页面顶部出现站点地址：`https://<你的用户名>.github.io/<仓库名>/`。

`.nojekyll` 已经在目录里，作用是跳过 Jekyll 处理，保证文件名以下划线/点开头的资源按原样发布。

> GitHub Pages 对**公开仓库**免费；私密仓库的 Pages 需要付费套餐。
> 这个目录里没有任何密钥，Token 只存在手机浏览器 `localStorage`，所以仓库公开是安全的。

更细的 Pages 操作和更新部署见 [github-pages/README.md](../github-pages/README.md)。

**验证**（PowerShell，替换尖括号）：

```powershell
(Invoke-WebRequest -UseBasicParsing "https://<你的用户名>.github.io/<仓库名>/").StatusCode
(Invoke-WebRequest -UseBasicParsing "https://<你的用户名>.github.io/<仓库名>/manifest.webmanifest").StatusCode
```

两个都应为 `200`。再用手机浏览器打开同一个地址，能看到深色页面和「未配置」状态。

## 3. 手机端首次配置

1. 手机浏览器打开 Pages 地址；
2. 点右上角「未配置」，展开配置面板；
3. **GitHub Personal Access Token**：粘贴第 1 步的 `ghp_...`；
4. **Gist ID**：先留空；
5. 点 **创建新 Gist**。成功后会提示「创建成功，Gist ID 已填好」，输入框里出现一串十六进制 ID；
6. 点 **保存并同步**，状态点变绿、显示「已同步」。

此时 GitHub 你的账号下会多一个私密 Gist，文件名为 `taskbar_todos.json`。

**验证**：

- 页面右上角显示「已同步」，底部显示上次同步时间；
- 在页面上添加一条「测试待办」，刷新页面后仍然存在；
- 打开 `https://gist.github.com/<你的用户名>`，能看到一个私密 Gist，内容是 `taskbar_todos.json`，JSON 里有 `"schema": 2`；
- 手机浏览器菜单里选「添加到主屏幕 / 安装应用」，桌面出现「任务栏待办」图标。

> 记下这个 **Gist ID**，电脑端要填同一个。Token 和 Gist ID 可以稍后在手机配置面板里修改（Token 输入框是密码型，只显示圆点，不会明文显示）。

## 4. 电脑端安装（两条环境路线，任选一条）

先打开 **Anaconda Prompt**（不是普通 PowerShell，除非你已把 conda 加进 PATH），进入项目目录：

```bat
cd /d "G:\deepseek harness\win11-taskbar-lyrics"
```

> 若你用的是 **PowerShell**（提示符是 `PS ...>`），`cd /d` 会报“找不到接受实际参数”，去掉 `/d`：`cd "G:\deepseek harness\win11-taskbar-lyrics"`。CMD 里才需要 `/d`。

### 路线 A：Python 3.11 + winsdk（推荐，SMTC 支持成熟）

**本机已经创建好项目专用环境 `taskbar-lyrics`**（Python 3.11.15 + PyQt6 6.11.0 + requests + winsdk），直接激活即可，无需再装：

```bat
conda activate taskbar-lyrics
python --version
```

如果换了机器、环境不存在，用下面的命令重建：

```bat
conda create -n taskbar-lyrics python=3.11 -y
conda activate taskbar-lyrics
python -m pip install -r desktop\requirements.txt
```

**验证**：

```bat
python --version
python -c "import requests, winsdk; print('requests', requests.__version__); print('winsdk OK')"
python -c "from winsdk.windows.media.control import GlobalSystemMediaTransportControlsSessionManager as M; print('SMTC OK', M.__name__)"
```

预期依次输出 `Python 3.11.15`、`requests ...`、`winsdk OK`、`SMTC OK ...`。

### 路线 B：Python 3.13 + pywinrt 拆分包

本机 base 是 Python 3.13.9，`winsdk` 没有 cp313 轮子，改用 pywinrt 的拆分包：

```bat
python -m pip install PyQt6 requests "winrt-Windows.Media.Control>=3.2.1"
```

注意 `>=` 必须加引号，否则 CMD 会把 `>` 当重定向。

**验证**：

```bat
python --version
python -c "import requests, PyQt6; print('requests', requests.__version__); print('PyQt6 OK')"
python -c "from winrt.windows.media.control import GlobalSystemMediaTransportControlsSessionManager as M; print('pywinrt OK', M.__name__)"
```

预期输出 `Python 3.13.9`、`requests ...`、`PyQt6 OK`、`pywinrt OK ...`。

### 4.1 也可以用 `install_deps.bat`

```bat
cd /d "G:\deepseek harness\win11-taskbar-lyrics\desktop"
install_deps.bat
```

它做三件事：检查 `python` 是否存在、升级 pip、`pip install -r requirements.txt`。`requirements.txt` 用环境标记自动选后端：

```text
PyQt6>=6.6
requests>=2.31
winsdk==1.0.0b10; python_version < "3.12"
winrt-Windows.Media.Control>=3.2.1; python_version >= "3.12"
```

所以 3.11 环境装 winsdk，3.13 环境装 pywinrt。脚本必须在**已激活目标环境**的 Anaconda Prompt 里跑，否则会把依赖装到 base。

### 4.2 无界面自检（强烈建议先跑）

```bat
cd /d "G:\deepseek harness\win11-taskbar-lyrics"
python desktop\taskbar_widget.py --selftest
```

它会用 offscreen 平台启动 1.5 秒后退出，打印三行：

```text
MEDIA_BACKEND=winsdk
CONFIG=C:\Users\<你>\AppData\Roaming\Win11TaskbarLyrics\config.json
SELFTEST OK
```

- 路线 A 期望 `MEDIA_BACKEND=winsdk`；
- 路线 B 期望 `MEDIA_BACKEND=pywinrt`；
- 若为 `MEDIA_BACKEND=none`，程序仍能启动，但只能读网易云窗口标题，歌词不精确；按 4 节重装媒体后端并重启；
- 若报 `ModuleNotFoundError: PyQt6`，说明依赖装到了别的环境，回到 4 节确认 `python` 指向。

### 4.3 启动

```bat
cd /d "G:\deepseek harness\win11-taskbar-lyrics"
python desktop\taskbar_widget.py
```

或双击 / 运行：

```bat
cd /d "G:\deepseek harness\win11-taskbar-lyrics\desktop"
run.bat
```

**验证**：

- 主任务栏上出现一条深色半透明胶囊，主行显示「🎵 任务栏显示器已就绪」或当前歌词；
- 鼠标滚轮能切换副行内容；
- 右键菜单能打开，包含「显示模式」「未完成待办」「立即同步」「配置 GitHub Gist 云同步」「重新对齐任务栏」「打开数据目录」「关于」「退出程序」；
- 托盘区出现音符图标（若系统托盘可用）；
- `%APPDATA%\Win11TaskbarLyrics\app.log` 最后几行有「启动 Win11TaskbarLyrics v1.1.0，媒体后端=…」。

## 5. 两端绑定

1. 在电脑端**右键任务栏胶囊** →「⚙️ 配置 GitHub Gist 云同步」；
2. **GitHub Token**：粘贴与手机端相同的 `ghp_...`；
3. **Gist ID**：粘贴第 3 步创建的 ID（**不要**点「创建新 Gist」，除非你想换一个新库）；
4. 点 **测试连接**，应提示「已连上 Gist，当前云端有 N 条待办」；
5. 点 **Save**（保存）。程序会清空旧 ETag、立即同步一次。

**验证（端到端）**：

1. 手机端添加一条「明天 09:00」的待办；
2. 电脑端右键 →「🔄 立即同步」，或等 30 秒；
3. 胶囊副行出现该待办；右键菜单「未完成待办」里也能看到；
4. 电脑端点一次完成（到点提醒时左键，或右键菜单里点该条），手机端回到前台/刷新后显示已完成；
5. 托盘悬停提示里有「未完成 N 条 · 最近同步 HH:MM」。

**常见绑定错误**：

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| `GitHub Token 无效或已过期（401）` | Token 错、过期、被撤销 | 重新生成 Token，两端更新 |
| `GitHub 拒绝访问（403，通常是限流或无 gist 权限）` | 没勾 `gist`，或限流 | 改 Token 权限；等限流窗口 |
| `Gist 不存在（404）` | Gist ID 错，或 Gist 被删 | 核对 ID；用「创建新 Gist」重建 |
| `Gist 中缺少 taskbar_todos.json 文件` | 填了别的 Gist | 换回正确 Gist，或让程序创建 |
| 两端都「已同步」但互不可见 | Token/Gist ID 不是同一组 | 两端逐字符核对 Gist ID |

## 7. 升级（v1.0 → v1.1 或后续版本）

### 7.1 升级前

1. 打开 Gist 页面，点 **Download** 或 **Raw** 备份一份 `taskbar_todos.json`；
2. 退出电脑端（右键 →「退出程序」，或托盘 →「退出」）；
3. 手机端确认没有未同步的改动（状态不是「同步失败」，底部没有「有本地改动待推送」）。

### 7.2 升级手机端

把新的 `github-pages/` 文件覆盖到 Pages 仓库，提交推送：

```bat
cd /d "<你的 Pages 仓库目录>"
git add .
git commit -m "update: v1.1"
git push
```

等 Pages 重新发布后，手机刷新页面。Service Worker 是**网络优先**，联网时会拿最新外壳；若仍是旧界面，强制关闭标签页再打开，或在浏览器设置里清除该站点缓存。

### 7.3 升级电脑端

用新代码覆盖 `desktop/`。如果你已经在用 v1.1，`%APPDATA%\Win11TaskbarLyrics\config.json` 不用动；从 v1.0 升级时没有这个文件，需要重新填 Token + Gist ID（见 7.4）。然后重新安装依赖并启动：

```bat
cd /d "G:\deepseek harness\win11-taskbar-lyrics\desktop"
install_deps.bat
run.bat
```

若用打包版，重新执行 `build_exe.ps1`，替换 `dist` 下的文件；开机自启快捷方式指向同一路径时不用改。

### 7.4 数据迁移

- 数据文件仍是 `taskbar_todos.json`，无需手动转换；
- v1 条目第一次被读取时自动归一化：`remind_time` → `remind_at`，`createdAt`/`updatedAt` → `created_at`/`updated_at`，缺失 `id` 自动补，缺失 `remind_date` 的旧提醒按**创建当天**理解；
- 如果旧数据连 `created_at` 都没有（v1 手机端早期条目可能如此），归一化会填 `1970-01-01`，旧提醒不会到点；升级后请给这类条目重新设置提醒日期；
- 旧数据没有 `tombstones`，读取时会自动归一化为 schema 2；只有发生一次实际推送（新增/编辑/完成/删除）后，云端文件才会写成 `schema: 2` 并带上 `version` 与 `tombstones`。只是打开/同步不会改写文件；
- 电脑端配置不会从 v1.0 的 `~/.win11_taskbar_lyrics_todo.json` 自动迁移，需要在设置对话框重新填 Token + Gist ID；
- **两端必须一起升级**。v1.0 客户端不认识墓碑，同时在线时可能把删除记录覆盖掉。

**验证**：手机端和电脑端都能看到升级前的全部未完成待办；删除一条后等 30 秒，两端都不再出现；`--selftest` 输出 `SELFTEST OK`。

## 8. 重置

### 8.1 只重置电脑端本地

先退出程序，再删除数据目录：

```powershell
Remove-Item -Recurse -Force "$env:APPDATA\Win11TaskbarLyrics"
```

这会清空 `config.json`（Token/Gist ID/位置/模式）、`state.json`（本地文档缓存/ETag）、`app.log`。**云端 Gist 不受影响**，重新启动后重新填 Token + Gist ID 即可拉回全部待办。

### 8.2 重置手机端本地

在浏览器设置里清除该 Pages 站点的数据，或在开发者工具 Console 执行：

```javascript
Object.keys(localStorage)
  .filter((key) => key.startsWith('tbl.') || key === 'gh_token' || key === 'gh_gist_id' || key === 'local_todos')
  .forEach((key) => localStorage.removeItem(key));
location.reload();
```

清除后需要重新填 Token/Gist ID；云端数据仍在。

### 8.3 重置云端

- **只清空待办**：在手机端点「清除已完成」，或逐条删除；删除会写墓碑并同步到电脑端；
- **彻底换库**：手机端配置面板点「创建新 Gist」，然后把新 Gist ID 填到电脑端；旧 Gist 可在 GitHub 上删除；
- 删除 Gist 后，仍指向旧 ID 的一端会报 404，必须换 ID。

### 8.4 取消开机自启

```powershell
powershell -ExecutionPolicy Bypass -File "G:\deepseek harness\win11-taskbar-lyrics\desktop\install_autostart.ps1" -Uninstall
```

## 12. v1.3.0 新功能配置（AI / 周报 / 记忆 / 账本）

升级到 v1.3.0 后，右键任务栏胶囊 →「⚙️ AI / 邮件 / 记忆设置」，按需填写：

| 功能 | 需要准备 | 默认值 |
| --- | --- | --- |
| AI 拆解 / 评价 | OpenAI 兼容 API 的 Base URL、模型、Key | `https://api.deepseek.com` / `deepseek-chat` |
| 周报邮件 | Gmail 邮箱 + **应用专用密码**（Google 账号 → 安全性 → 两步验证 → 应用专用密码） | `smtp.gmail.com:465`，周日 21:00 |
| 每日记忆 | 私有仓库 `luongthimydieu/taskbar-memory` + 带 `repo` 写权限的 Token | 每天 23:30 |
| 账本 | 点「创建账本 Gist」自动生成独立 Gist；手机端填同一个 Gist ID | 无 |

- 记忆仓库已初始化为私有仓库，Token 需要 `repo` 权限（Gist Token 只有 `gist`，不能写仓库）；
- 账本使用独立的 `taskbar_ledger.json` Gist，待办继续用 `taskbar_todos.json`；
- 所有凭据只写本机 `%APPDATA%\Win11TaskbarLyrics\config.json`，不会提交到仓库；
- 详细排错见 [04 常见问题](04-常见问题.md) 的「v1.3.0 新功能怎么配置」。

### 更新手机端（v1.3.0）

`github-pages/` 目录更新后，按第 2 节的方法重新推送 Pages 仓库即可；Service Worker 已升到 `tbl-shell-v4`，手机刷新/重开页面后生效。手机端配置里需要新增「账本 Gist ID」（与电脑端一致）才能同步账本。
